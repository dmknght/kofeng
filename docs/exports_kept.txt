exports_kept.txt - what is exported, defined or named in the tree and has no caller in the
engine, and why each stays. One place, so a later audit does not rediscover it as a finding.
Every entry below was checked by reading, not assumed: a name with no reference outside its
definition and declaration, over .c .h .py .sh Makefile and the docs, with kofexamine/ counted
as a user.

3. MODULE-ABI VOCABULARY. The alias macros of kofmod/ (a define whose body is one kgenome_ /
   kuncoat_ name) and the enumerators and macros the ABI headers carry are the module contract:
   a module may use any of them and the engine does not need to. 199 aliases, 66 with no user
   outside kofmod/ today. They change only with the ABI version, which is not this change's to
   bump.

4. UNREFERENCED MACROS THAT ARE MEMBERS OF A SET. A value of a documented set (a wire layout, a
   flag word, a table of register numbers) is kept when its siblings are used, because the set is
   the statement and a hole in it reads as an oversight:
     KGENOME_NUCLEO_F_LOW8, _F_LOOP (flag bits of a node)
     KGENOME_CELL_SEG_ES, _SEG_CS (the segment numbers beside _SS _DS _FS _GS)
     KGENOME_SECF_ORIGIN_MASK, _PLAIN, _COMPRESSED, _VIRTUALISED, _STATE_MASK (section flags)
     KGENOME_X86_ACC_R, _ACC_CR, _ACC_CW, _M_STACK, _M_STRING, _M_AG (operand access / memory bits)
     SCN_CNT_INIT_DATA (pe_image.c, beside SCN_CNT_CODE); ARJ_NAME_AT (arj_parse.c) and B_CRC,
     F_HOST_OS, F_TIME, F_ATTR (rar_parse.c): offsets of a header layout whose other fields are
     read; TL_G0 (script_parse.c, beside TL_G1 and TL_G2); KOF_MEMO_UNKNOWN (kofmatch.h, the
     memo's 0); KUNCOAT_LZHUF_NP (lzhuf.h, beside _NC and _NT)
   Deleted instead, because they were helpers or tunables and not members of a set:
     KGENOME_NUCLEO_CTX, _AS_KERNEL, _BASE, _DENSE_MAX; KGENOME_CELL_NREG; DIAG_NAME_MAX;
     NORM_MIN_SAVE; HEUR_EMU_MAX.

6. NAMES THAT STAY BECAUSE A POSITION, A LAYOUT OR AN OLD PACK CARRIES THEM, and that nothing acts on:
     reserved_0 .. reserved_9 (struct kof_content, kofmod/kofcontent.h): vtable positions of three
        measures that were taken out (0-2) and of the cure and image-address slots that went with the
        old verdict (3-9: cure_offer, cure_patch, cure_truncate, pz_clean_end, pz_is_code,
        pz_addr_to_off, pz_unmask). NULL by design; the order of the vtable is the module ABI.
     reserved_0 (struct kof_obj_ctx, kofmod/kofctx.h): the position of the module's report slot.
     reserved_heur_phase, reserved_heur_want, reserved_heur_level, reserved_heur_predict,
        reserved_cure, reserved_disease, reserved_disease_type (struct kof_pack_mod,
        databases/pack/dbcore.h): fields of a pack record that carried the old verdict's level, a
        heuristic rule's stage and the module's own disease. Written as zero, read by nothing; the
        record layout is the pack format and does not move.
     KOF_PACK_RETIRED_HEUR (databases/pack/dbcore.h): the kind value 2 of a heuristic module. A
        pack that holds one is refused by the validator and says so; the value is kept so that it
        is never given a second meaning.
     reserved_level (struct koffridge_verdict, libkoforbit/fridge/koffridge.h): the position of the
        finding level in the cache file; the file layout and its FILE_VERSION do not move.
     "syndromes.kdig" (databases/dbloader_packs.c, kof_db_refuse_retired): the one name of a removed
        pack kind that survives, because a database directory built before it was removed may still
        hold the file. The loader refuses it with a stderr line and counts it in diag_packs_refused
        (kdb_diag_packs_refused): it is never taken for an absent file.
     "kof_cure", "kof_heur" (ksigbuilder/ksb_image.c): the two entry names of a module that the
        build refuses by name. An image that still defines one is not built, with a line saying
        the entry is retired; the name is what is refused.
