OTHER FINDINGS THAT ARE NOT A KM_CHECK (they have no observable in the plain build, or are not reachable from a file):
  - analyzers/parsers/processes/proc_parse.c:118 reads the caller's record as `const struct kof_proc_rec` (8 byte alignment) from
    the bytes given to kscan_bytes/as_format: a buffer that does not start 8 aligned is a misaligned member access. UBSAN reports it
    (hostile_engine_scan.c rounds its sizes to 8 for that reason); x86 does not mind, a strict-alignment target would.
  - kof_script_is_block has no upper bound on `open` in its second loop: an island starting past the end of
    the object reads past it. Every caller passes islands it found inside the object, so no file reaches it.
  - kof_dsrc_reads / kof_scan_new / kof_prod_ran take unvalidated arguments (a NULL callback, a count past the table, a NULL
    engine, a product past the enum); internal callers never pass them. Recorded here, not asserted.
  - kof_gr_u16 and kof_gr_u64 (kofmod/kofdiagtree.h) read the record they are given with no NULL guard, as kof_gr_in did before it was
    given one (api_engine_detect.c: a NULL record is NONE); they take a record the caller found, and kof_gr_rec answers NULL past the last.
  - KOF_MEMMEM_FAIL_MAX / KOF_MEMMEM_GIVE_UP exist only in the Windows branch of kofplatform_os.h (the POSIX build calls the C library memmem);
    they are listed and cannot be named by a test that builds on this host.
  - A pack carries a CRC-32 and no signature (databases/pack/dbcore.h states the threat model: write access to the database is write
    access to the process). pack_fuzz reseals after mutating, and that is what a hostile pack with a valid CRC looks like.
